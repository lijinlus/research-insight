# Research Insight

把研究想法推进到一个可判断的决策：研究问题为什么值得解决，现有知识缺在哪里，新增主张是什么，用什么证据支持或推翻，下一步做什么。

这里的“亮点”指有依据的知识增量，而不是更响亮的标题。优先找能改变研究决策的缺口；不要把一个普通方案重新命名后当作创新。

## 根据材料选择工作方式

- **探索**：只有主题、类比或模糊想法。提出少量相互可区分的假设，说明各自可能新增什么知识，比较价值与验证成本，推荐先检验哪一个；不直接堆网络、Agent 或 RL 模块。
- **诊断**：已有 idea、proposal 或方法。检查问题、近邻差异、解释与证据链，指出最可能让贡献不成立的一处，并给出修复方向。
- **重构**：已有代码、结果或草稿。先确定结果真正支持什么，区分探索发现与确认性检验，再组织贡献。新发现的解释需要新验证，不能把事后故事伪装成事先假设。
- **拆解论文**：用户希望从论文学习研究思路。读原文，定位主张、关键证据、未排除的解释与适用边界，提取可迁移的研究操作。没有官方评语时，不把自己的分析写成“获奖原因”。

从用户材料和获授权的项目文件获取上下文，利用已知的数据基础、时间/算力和产出目标判断可行性；未提供的条件不臆测。仅缺少会改变研究选择的信息时，提出少量具体问题，同时推进不依赖答案的工作。区分用户报告、已检查的材料、自己的推断和待验证假设。

需要产生新思路、寻找亮点或组织研究主线时，阅读 [研究操作库](references/research-moves.md)，选择与材料相符的操作。探索时可以先形成未核验的候选，再检查近邻与证据；保留有希望的部分，不因信息不完整直接否定方向。诊断单一实验或已明确的技术问题时无需遍历操作库。

需要从具体论文学习问题与论证设计时，可读 [35 篇原文案例索引](references/paper-library/index.md)，按问题选择少量卡片，再回到对应原文。[跨论文归纳](references/paper-library/synthesis.md)提供有出处的研究操作。不要默认加载整个案例库；逐篇分析标明读取范围，未复现实验或全面审计证明，也不能替代当前课题的近邻检索。

下列环节按当前问题选用，不要求四种模式都执行一遍。已核对的材料可以沿用，新增检索聚焦会改变当前判断的缺口。

## 1. 先明确知识缺口与主张

将“想做什么模型”转成“希望知道或改变什么”。尽量补全：

> 对【对象/条件】中的【问题或知识缺口】，我们提出/检验【新增结论、能力或资源】；通过【证据与必要比较】判断其成立程度，结论适用于【范围与边界】。

不要为填模板编造根因或现象。方法创新、理论、数据、系统、基准、可靠的负结果都可能有贡献；没有惊艳现象不等于不能做。可以有多个贡献，但要说清它们之间的关系及各自的证据。

这是一种可选的主张结构。只有声称“为什么”时才追加机制假设和竞争解释；纯算法改进、资源建设和理论问题可以直接说明问题、增量与证据。

至少分清：

- **问题价值**：谁在什么真实条件下受影响？解决后改变什么判断或能力？“领域热门”和“尚未有人组合 A+B”不足以回答。
- **预期知识增量**：相较最接近的工作，新增的是哪条结论、能力、适用条件、证据或资源？它是否只是已知思想在新数据上的复现？
- **当前证据强度**：这是直觉、初步观察、受控结果，还是有明确假设的理论结论？主张不得超过证据。
- **投入可行性**：关键数据、实现基础和验证成本是否可承受？优先级同时考虑知识价值与约束，不只看新奇程度。

涉及取舍时，明确要改善什么、哪些能力需保持、允许付出什么代价。贡献可以是质量—存储、可靠性—预算等边界的改善；不要求所有指标同时领先。不要把统一接口等同于训练简单，把目标侧少样本等同于没有源监督，或把行为抑制等同于知识删除。

## 2. 用近邻工作校准贡献

当需要判断创新性或准确解读论文时，检索并阅读一手来源：原论文、正式 proceedings、作者代码与附录。围绕任务、关键假设、机制和评测设定检索，不能只搜自己给方法起的名字。

先覆盖最接近的少量工作，再根据影响判断的缺口追加检索；不要为凑篇数加入无关名作。对关键近邻，给出来源、共享之处、确切差异、差异是否已获证据支持。能定位时附章节、定理或图表；只读到摘要就注明，不能据此断言论文没有做某实验。

不能检索、原文不可得或覆盖不足时，仍可分析研究逻辑，但将创新性标为待核验，并列出会改变判断的具体检索项。检索未发现不等于“首次”。不凭记忆杜撰论文、实验、获奖状态或审稿标准。

拆解优秀或获奖论文时，把“论文做了什么”“官方评价”“自己的推断”分开。获奖样本可提供启发，不能单独证明某种方法导致获奖；用户希望归纳规律时，建议加入同类普通论文和反例作对照，不自动扩成大型文献工程。

## 3. 检查最威胁主张的缺口

阅读 [证据与实验设计](references/evidence-design.md)，按主张类型选择证据标准。

找出最可能推翻主张或削弱贡献的缺口：经验主张检查数据污染、预算、容量、调参、监督、指标或选择性报告；理论主张检查假设、反例与已有定理覆盖；资源/系统主张检查用途、可靠性和已有替代品。优先展开影响当前决策最大的一项。

当主张涉及机制或根因时，提出目标解释与竞争解释在什么条件下给出不同预测。模块消融或相关性本身通常不能识别根因；若现有实验无法区分，就建议针对性对照或收缩主张。只声称有效性时，用公平比较与可靠测量支持结论，不强制证明唯一根因。

跨领域类比应落到可操作假设：原领域的哪条原理、目标任务的哪个瓶颈、可观察的独特预测。不能用“像大脑”“多 Agent 有分工”替代证据。

核对证据是否针对同一对象：代理分数、模型自报告、内部表征、采样行为与真实用途各支持不同层次。理论结论保留对象、量词、误差尺度和资源模型，并说明哪些假设由实际实现满足。只有初始化时成立的性质不能写成全程保证；作者指向的未读附录不算已检查证据。

## 4. 设计最小而有判别力的下一步

优先选择信息价值高、成本低的实验或理论检查；能用现成模型、简单基线或小规模数据回答时，不先训练完整系统。小实验用于筛查假设，其规模与代表性也限制结论。

给出可执行的实验卡：操纵变量、固定条件、必要对照、指标与分析单位、数据切分、什么结果支持/削弱哪条主张，以及通过后才值得投入的下一步。无法预定数值阈值时说明如何用基线波动、实际用途或统计功效确定，不能随意编一个提升百分比。

需要归因时，将系统竞争力比较与匹配数据、监督、预算的受控比较分开；修复某类错误时保留本应答对的正对照，避免靠一律拒绝或一律怀疑改善局部指标。自适应搜索/多轮反馈会改变数据分布，验证时检查评分器、停止决策和共同信息来源。具体测量与成本口径见证据设计参考，按任务选用。

以上实验卡用于经验验证。理论问题可以优先交付证明路线、关键子命题或反例搜索；拆解论文时评估作者已有证据，用户要求迁移到自己的课题后再设计新实验。

区分“实现故障”“统计信息不足”和“假设受反证”，不把一次无显著差异直接判成假设为假。根据数据依赖结构报告不确定性，不把相关样本当独立重复。

当任务涉及量化、金融预测、因子或回测，再阅读 [Quant/ML 检查](references/quant-ml.md)。不默认拥有数据、GPU 或已完成实验；除非用户要求执行，不自动启动训练或改写研究代码。

## 5. 交付研究决策，而不只给形容词

按模式交付最有用的产物，默认只展开主要瓶颈和一个优先下一步：

| 模式 | 默认产物 |
| --- | --- |
| 探索 | 少量候选主张及其差异、价值与成本比较、推荐先验证的一项。未核验候选可以保留，但不宣称新颖性已成立。 |
| 诊断 | 当前判断与依据、最影响贡献的一处缺口、修订后的主张与最小验证卡。 |
| 重构 | 现有主张与证据的对应关系、哪些可保留/需收缩、最重要的补证项，以及有依据的研究主线。 |
| 拆解论文 | 作者解决的缺口、核心知识增量、原文关键证据与局限、可迁移的研究操作及迁移条件；无需给读者的课题作投入决策。 |

需要组织论文主线时，给出“缺口 → 主张 → 关键证据 → 边界”和最重要的一张图应该回答什么。每个连接标明证据或待补验证，证据不足时保留假设语气。

让小节围绕必须回答的问题组织：贡献点各由哪项结果、定理或资源验证支持，支持到哪一层。优先展示最能区分新主张与简单替代的证据；不强制首页命名现象、单一claim或“现象—根因—方法”格式。被数据否定的预设解释可以删改，新的解释保留探索身份。

研究投入建议可为优先验证、收缩/换角度或暂缓，同时说明证据充分程度；证据不足时给出先补什么，不把未知等同于没有价值。这不是录用概率预测。不要把新颖性、可信度、成本等相加后打总分，掩盖关键缺陷。单一问题无需生成整份报告。默认中文沟通，保留必要英文术语。
