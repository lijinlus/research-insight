# 研究操作库：从材料产生可检验的主线

本文件保留四维与六种范式的通用研究操作，不嵌入具体论文、业务或开发用例。操作用于提高当前候选，不是经统计验证的获奖规律或所有研究的必选分类；未覆盖的贡献路径可以直接讨论。

## 四个维度怎样转成研究产物

| 文章观点 | 主动执行的研究操作 | 应交付什么 |
| --- | --- | --- |
| 主题立意强 | 找重要但未被系统表述的现象、经验解释缺口或真实约束；指出谁的哪项判断因此改变 | 有依据的问题定位与价值说明 |
| 技术思路牛 | 从瓶颈推导机制；尝试跨领域成熟工具、更换表示或删去不必要设计 | 核心洞察、技术草图与区别于简单替代的预测 |
| 实验效果夯 | 选择能测到目标能力的尺子、受控比较和边界测试 | 支持或推翻主张的关键实验/证明，而非只列排行榜 |
| 叙事能力佳 | 提炼工作定位，将洞察、方法与证据组织成读者能跟随的论证 | 候选主线、关键图职责；需要时给标题与引言推进关系 |

四维可以共同作用，但不要求每项都创造独立贡献。研究叙事的具体操作见 [research-story.md](research-story.md)。

## 怎么使用

先识别已有材料：观察到的失败、未经检验的默认假设、尚无解释的规律、测量盲区、真实应用约束，或多套方法之间的共同结构。顺着有材料支撑的操作展开，也可以暂留不同解释；没有明显匹配时保留原问题，不强行追求反直觉或根因故事。

探索可以从有意思的观察、类比或技术草图开始，随着讨论逐步说清：**什么问题值得研究 → 核心洞察是什么 → 可能新增什么认识或能力**。有希望的方向再形成区分性预测或便宜检查；暂时说不清的环节可以留作下一轮问题。需要收敛时，再比较价值、近邻重合与验证成本。

已有结果时，按证据选择主线；若想提出新解释，明确标为探索假设。不要为了符合某种范式，事后挑选窗口、任务或指标。

## 六种范式：保留原名，按材料选择

下面的名称沿用 Story 文章，具体操作依据原文案例修订。可以组合，也可以只借用其中一个问题来展开思考，无需完整采用整条路线。

## 1. 根因手术刀：把“无效”拆成可区分的原因

**适用材料**：可重复的失败或条件差异，且已初步检查实现与评估是否正确。

**研究操作**：列出竞争解释，寻找它们预测不同的条件；先诊断，再判断是否值得设计针对性方法。新方法有效与根因被识别是两个不同主张。

**候选主张**：在条件 C 下，变量 Z 的变化解释了部分失效；针对 Z 的干预改变了预期行为。若只能发现关联，就保留为有边界的现象主张。

**关键验证与图**：控制其他条件的干预、替代解释对照；图展示效果是否随目标变量按预测变化。单独移除模块后性能下降不够。不要未经区分就称“唯一根因”。

## 2. 反直觉重构：找出默认假设成立的条件

**适用材料**：有来源可定位的惯常设计或明确假设，其收益或必要性尚未在当前条件下检验。

**研究操作**：精确定义假设，并在信息和预算合理可比时改变它的强度或适用条件。先确认这确是已有工作的假设，不把夸张口号当作领域共识。

**候选主张**：假设 A 的收益依赖条件 C，在 C 改变时出现成本或失效；替代设计解决其中一部分。

**关键验证与图**：假设强度/环境条件与效果的曲线、正反例、预算匹配。只找到一个反例可以界定边界，未必能推翻整套方法。结果符合常识时也可有价值，不制造反直觉。

## 3. 理论照亮经验：提出与真实操作相连的形式问题

**适用材料**：稳定的经验规律、可证明的能力差异，或尚未解决的算法/复杂度问题；理论研究也可直接从形式问题出发。

**研究操作**：明确对象、假设、比较类和量词，寻找能推出可区分预测的简化模型或命题。说明形式设定如何对应实际方法，以及哪里不对应。

**候选主张**：在假设 A 下，操作 M 具有某能力、边界、复杂度或误差性质；这给出对条件 C 的预测。不要为装饰方法增加无关引理。

**关键验证与图**：证明或明确尚未证明的命题、反例与边界；涉及经验解释时，用能区分理论预测的实验搭桥。表达能力不自动推出可学习性、优化效率或现实任务表现。

## 4. 新基准暴露失效：把未测到的能力变成可验证问题

**适用材料**：现有分数与实际能力不一致、被平均值掩盖的失败，或现有协议没有覆盖的必要条件。

**研究操作**：先定义要测量的能力和用途，再设计任务、对照和指标。检查评分器是否可靠、是否存在捷径，是否仅因任务更难而普遍降分。

**候选主张**：现有测量不能区分能力 X 与混杂 Y，新协议在明确范围内改善这种区分。

**关键验证与图**：已知正负例、匹配难度的对照、适当的人工或独立核验；图揭示旧分数掩盖了哪类行为。新基准让模型变差或改变排名，本身不证明测得更准；避免挑选仅有利于自家方法的任务。

## 5. 社会价值叙事：让真实痛点与约束改变问题定义

**适用材料**：离线设定与具体使用者的需求、可得信息、资源或失败代价存在差距。

**研究操作**：将具体约束写进数据、目标或协议，说明它如何改变已有方法的适用性。真实用途可以贡献重要任务与资源，不必夸成全新的通用机制。

**候选主张**：在约束 C 下，原来的比较/方法不足以回答需求，新协议或方法在对应效用上带来可检查的增量。

**关键验证与图**：约束存在的证据、可行的替代方案、效用与失败代价；图展示真实约束怎样改变结论。若只测了代理指标，说明它与实际用途的距离，不声称已经产生社会影响或部署收益。

## 6. 极简统一美学：寻找有实际增量的共同结构

**适用材料**：多个任务共享结构，或多套组件有重复计算、冗余假设和难以维护的接口。

**研究操作**：提出一个共同对象、表示或操作，说明原来的多个任务如何由它得到，以及统一引入了哪些代价。

**候选主张**：共享结构 M 在条件 C 下覆盖任务集合 T，并改善一致性、质量、成本、可扩展性或实现复杂度中的明确一项。

**关键验证与图**：逐任务强基线、同信息与预算的比较、迁移或负迁移、质量与成本边界。一个 API 或更少模块不自动构成知识增量；统一也可能牺牲专项能力。

## 技术洞察的另外三个入口

六种范式描述问题与论证路径。形成技术候选时，还可使用立意文章强调的以下操作：

- **跨领域迁移**：挑出源领域有依据的原理或工具，写明它对应目标任务的哪个瓶颈，哪些对象/假设能映射，形成相较简单替代可区分的预测。先比较迁移原理本身与简单替代，不先复制完整架构。
- **更换表示或优化对象**：检查困难是否由当前坐标、任务拆分、度量或目标带来；尝试在新对象上把原本复杂的操作变简单。说明究竟简化了哪个环节，以及引入的代价。
- **把复杂设计压缩为关键机制**：用一句可解释的话说明哪个操作解决哪个障碍，再检查额外组件是否必要。保留确有用途的多个组件；一句话解释机制是理解检查，不是限制模型结构或贡献数量。

## 从研究操作到论文主线

选定候选后形成一个论证骨架：

> 为什么这个缺口重要 → 我们看到了什么关键洞察 → 因此改变什么对象、机制或测量 → 哪项证据最有判别力 → 什么情况下不成立。

将推荐角度写成能说明对象、缺口、洞察与潜在增量的定位句，未验证部分保留假设身份。随后按需用 [研究叙事](research-story.md)选择论证路线、安排关键图与引言；证据缺失时明确补证方案。无需硬凑固定格式。
