# 研究叙事：让立意、技术洞察与证据形成主线

以下是按当前材料组织论证的通用操作，不预载论文案例，也不提供获奖因果规律或录用保证。

## 根据研究阶段使用

- **选题/方案阶段**：把尚待验证的洞察组织为候选论证，反推最值得先获得的证据。可以提前设计核心图，但仅描述它将区分什么，不填想象中的结果。
- **已有结果阶段**：从实际支持的结论组织研究主线，识别值得保留的亮点及欠缺证据。发现最初解释不成立时修订主线，新解释保持探索身份。
- **只读论文阶段**：解释作者如何推进问题、提出洞察、用证据支撑；区分原文、官方评语和自己的归纳。

## 1. 提炼工作定位与核心洞察

先用几句话回答：这项工作让读者新增什么认识或能力？问题为什么重要？最接近的工作留下了哪处具体缺口？新洞察为什么使技术路线或测量选择合理？

寻找能被记住的研究转折：被忽略的现象、捆绑优势中的代价、旧比较看不见的差异、改变可行性的真实约束，或让多项操作共享的对象。只有技术改善时，可以直接用质量—成本等明确增量定位，不必制造反常现象。

尝试用一句话说明“哪个原理/操作解决哪个障碍”。说不清时回到关键设计的必要性，而不是添加口号。多个贡献可以由一个重要问题连接，每项贡献仍需说明新增什么及其证据。

## 2. 选择与材料相符的论证路线

六种范式的生成操作见 [研究操作库](research-moves.md)。这里关注每条路线怎样组织论证。

| 原文章范式 | 可选的论证推进 | 最关键的证据或图应回答什么 |
| --- | --- | --- |
| 根因手术刀 | 可重复失效 → 竞争解释 → 可区分干预 → 设计回应 → 效果与边界 | 干预目标因素后是否出现预期变化；最强替代解释是否也能说明 |
| 反直觉重构 | 有来源的默认假设 → 未覆盖的条件/反例 → 更合适的问题定义或替代设计 | 收益是否依赖被捆绑的属性，在哪些条件发生转折 |
| 理论照亮经验 | 精确问题与比较类 → 形式对象 → 关键命题 → 证明与边界 → 必要的经验连接 | 命题究竟区分哪两类对象或资源；实际实现满足哪些条件 |
| 新基准暴露失效 | 用途要求 → 旧尺子遗漏 → 新操作化与对照 → 新观察 → 使用边界 | 已知正负例或最小对能否被正确区分，旧指标为什么看不见 |
| 社会价值叙事 | 具体使用者与失败代价 → 数据/部署约束 → 技术取舍 → 用途验证 | 新方法是否改变实际决策、覆盖或成本；代理指标离现实效果多远 |
| 极简统一美学 | 分立路线的共同结构 → 一个表示/操作 → 各任务读出 → 覆盖、质量与成本 | 统一发生在哪一层，是否有额外监督、后处理或专项能力损失 |

选择能解释当前主张与证据关系的路线，按需组合；不适合这些范式时直接组织当前任务的论证，不为归类预先认定原因。

## 3. 把最重要的增量放到读者最先看到的位置

需要命名现象或拟标题时，让名字帮助辨认实际对象或结论：研究了什么、改变了什么判断、条件是什么。优先考虑能准确传递结论或问题的标题；尚无结论时使用问题或条件化表述。名称不承担证明责任。

引言前部应尽早使读者明白问题价值、具体缺口和核心洞察。可用如下关系检查段落是否相接，而非固定四段模板：

> 为什么值得关心 → 现有做法在哪个具体条件不足 → 新洞察使什么选择合理 → 本文用什么证据建立增量。

可用一个例子、最小反例、受控现象或资源约束使缺口具体；理论论文也可直接从准确的形式问题开始。按用户需要提供定位句、标题候选或引言提纲，不自动改写整篇英文，也不设“前两段决定评分”之类未经核验的规则。

## 4. 先确定关键图的论证职责

从当前主张讨论关键图需要让读者看懂什么。想法尚早时，可以先画逻辑草图；准备验证时，再细化比较对象、操纵变量、必要对照与测量，详见 [证据设计](evidence-design.md)。图可以是质量—成本边界、反例、任务覆盖、机制干预或测量对照。概念图与实测结果应清楚区分。

让后续小节分别承担主张所需的论证职责：问题确实存在、设计或资源新增什么、为何有效（若声称机制）、适用于哪些条件。主表、受控实验与边界分析各有用途，不要求每篇同时包含所有类型。

## 5. 交付能推进研究的主线

材料较少时，先连起重要缺口与候选洞察，指出最值得获得的证据；技术细节与适用条件可以随讨论逐步明确。材料充分且用户要打磨稿件时，再给关键图职责与引言推进关系，区分已有支持与待核验部分。

可选的小表：

| 要让读者理解的内容 | 当前材料 | 还缺哪项有判别力的证据 |
| --- | --- | --- |
| 问题为什么重要，旧结论漏在哪里 | 用户观察、用途条件或已核验近邻 | 能使缺口具体的例子、比较或定义 |
| 新洞察为什么支持技术选择 | 原理、形式推导或受控发现 | 简单替代、关键干预或证明步骤 |
| 新增了什么，以及在哪些条件成立 | 结果、定理或资源验证 | 跨条件检查、成本或用途桥接 |

文章中的“说清一件事”用于检查核心增量是否清楚，不限制贡献数量；“技术极简”用于寻找必要机制，不要求模块越少越好；“拍大腿”用于寻找有价值的观察，不构成选题或投稿门槛。保留这些启发的积极操作，同时让主张强度随证据调整。
