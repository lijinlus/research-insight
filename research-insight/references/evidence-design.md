# 主张需要什么证据

本文件用于把“亮点”转成可以检查的证据要求。选择适合当前主张的部分，不要求每个项目同时做理论、基准、因果解释和 SOTA。

## 按主张类型匹配证据

| 主张 | 需要回答 | 常见越界 |
| --- | --- | --- |
| 现象或失败模式 | 现象如何操作化？在哪些代表性设定可重复？排除了哪些测量伪影？ | 少量精选例子推到所有模型；把特定任务上的相对变化写成普遍能力下降 |
| 机制或根因 | 哪项干预能区分目标解释与最强替代解释？有没有反向预测或负对照？ | 消融掉模块后变差，就称模块模拟了某种认知机制；用相关性宣布因果 |
| 方法或算法 | 与强且合理调参的基线相比，在哪些条件有实质改进？资源和信息是否公平？ | 只比过时基线；更多采样、数据或监督带来的提升归功于架构 |
| 理论 | 假设、结论、量词和复杂度模型是什么？与最近结果相比改进在哪里？哪些反例限制适用范围？ | 只给直觉推导就称定理；在受限模型中成立却声称解释所有实际系统 |
| 基准或评测 | 指标测到了什么能力？标注/生成可靠性如何？结果能否支持预期用途？ | 排名变化就说明新基准更有效；任务可被无关线索或污染解答 |
| 数据或系统 | 新资源/系统解决了什么瓶颈？相同用途下质量、覆盖、成本或可靠性改善如何验证？ | 把规模本身当全部贡献；排除失败请求和维护成本后声称更高效率 |
| 负结果或复现 | 原结论在什么范围内不稳定？实现、预算、功效与适用条件是否解释差异？ | “没跑出来”直接等于推翻原工作；把不显著当成等效 |

机制解释不是方法论文的强制条件。若只证实了有效性，就准确报告有效性；如要解释为何有效，再增加能区分解释的证据。

## 明确成功标准与比较对象

在会改变判断的地方，把四件事写清：**目标改善量、需保持的能力、可接受代价、允许的信息/反馈**。例如存储减少而渲染较慢可以是有用的取舍；无标签目标域适应与完全不接触目标域是不同协议。先比较同一工作点或质量—成本曲线，不把总分掩盖的退化抹去。

系统级主表回答“完整方案有无竞争力”；控制数据、容量、监督、预算和调参的比较才更接近“这项设计贡献什么”。主系统与小模型消融也不完全等价。不能完全匹配时说明剩余差异，不因此停止一切判断。

理论比较明确：对象与模型类、量词、oracle/可访问信息、误差距离、资源及成功概率。特别区分：

- 对原目标精确，还是对新定义的替代目标精确；子程序精确，还是整个算法无误差。
- 性质在初始化、单步局部干预、全训练过程或最终功能的哪一阶段成立。
- 存在性/可表示性、构造算法、搜索最优性、可学习性与实际效率。
- 实现是否满足定理条件。关键桥梁可先用低维、极端条件或简单反例检查；未核验的证明步骤明确保留状态。

例：[Sampling](paper-library/06-sampling.md)区分早停KL与原分布bounded-Lipschitz；[CaDyT](paper-library/09-cadyt.md)区分有限维核理论与RBF实验；[GeoRA](paper-library/26-geora.md)的初始化mask不等于持续更新support约束。

## 检查尺子是否真的测到目标

按当前任务选择最关键的一项：

- **构念与操作化**：标签、生成规则与名字是否一致？自报告分布、采样行为、内部表征与真实决策是不同对象；从另一模型的probe不能直接定位本模型失败阶段。
- **正反与不变性**：应对的相关变化能否改变得分，无关线索是否不应改变？修复坏例时同时保留应答对的互补组。结构一致性可由格式保证，语义正确仍需另测。
- **指标可被什么简单策略优化**：只拒绝正类可压低某类风险率；复合分数可因不同组成项同值；方向可反转的检测AUC远低于0.5仍可能高度可分。报告组成项/必要混淆，匹配所声称成功标准。
- **参照是否独立**：评测真值、训练标签、开发选择和自动judge是否共享源模型、知识库或summary？独立数据入口不一定意味着独立知识来源；与同一模型的另一条件一致不等于通过外部效度验证。
- **协议与统计单位**：基础事件、患者、原文、题目、派生最小对和重复rollout分别是什么？按共同祖先分组划分；用户模拟器、提取器与judge的失败也要抽查，重复系统运行的波动不全是目标模型的波动。

例：[Imperfective](paper-library/15-imperfective.md)的互补条件，[MediEval](paper-library/24-medieval.md)的条件风险率，[PolyGloss](paper-library/31-polygloss.md)的对齐与正确性，[CIG](paper-library/35-cig.md)的共享summary参照，分别展示上述不同问题。无需每项研究逐一套完。

## 成本与闭环的条件检查

声称效率时，只展开相关成本：数据/标签生成、预计算与初始化、训练和调参、部署时采样/搜索/重试、硬件/显存与通信。参数量、局部loss复杂度、FLOPs、epoch、墙钟、延迟与总设备数不能互代。若摊销，注明对多少任务/配置/请求摊销；只需一个输出的用户仍支付一次性成本。

闭环里，训练与部署分别能访问什么反馈？评分器引导搜索后，访问的状态与样本分布是否改变？比较等总token/调用或预算曲线；并行候选数与顺序轮数相同不保证同成本。除最终成功，按用途检查正确→错误、错误→正确、错误停止和无谓重试。多个模型共享输入/评分来源时，一致不能当作独立证据。

例：[GISP Table 3](paper-library/30-gisp.md)的多配置摊销，[Lychee-FD Appendix E](paper-library/22-lychee-fd.md)的多设备并行，[CURE Tables 2–3](paper-library/27-cure.md)的采样/迭代成本，[IVR §3](paper-library/19-evolutionary.md)的搜索分布变化。

## 最强替代解释表

仅列影响决策的少量解释。比如“多 Agent 提升来自专业分工”：

| 候选解释 | 区分预测 | 优先对照 |
| --- | --- | --- |
| 角色分工有独特作用 | 总预算相等时，角色互换/删除专属信息会有可预测影响 | 相同基础模型与信息、匹配预算的单 Agent 多次采样；固定其他条件的角色干预 |
| 更多推理与采样 | 提升随总采样/推理预算变化，并不依赖角色 | 单 Agent 在相同预算下采样、聚合；绘制预算与质量曲线 |
| 额外提示或信息 | 保留信息后，去掉角色也能取得类似提升 | 将同等信息和提示内容提供给无角色对照 |

这些仅是设计例子，不是已知结论。不要为了全排列做昂贵实验；先找最便宜、最可能改变决策的一个对照。对照无法完全匹配时，说明残余差异如何限制推断。

## 最小验证卡（经验研究）

- **待检验主张**：包含任务、范围和预期比较；不预写成功。
- **主要威胁**：最可能影响结论的偏差或比较缺口；涉及机制归因时，再列出竞争解释及其不同预测。
- **处理与对照**：修改什么，固定什么，最简单的有竞争力替代方案是什么。
- **数据与划分**：来源、可用性、独立分析单位、拟合与选择边界；明确开发数据与确认性留出数据。
- **测量**：主指标、必要的质量/成本约束、失败计数规则；指标如何对应主张。
- **不确定性**：哪些波动来自训练 seed、数据划分、任务或样本？按依赖结构选重复/区间方法，不套统一的 seed 数。
- **判别规则**：目标解释成立和替代解释成立分别预期什么；什么结果仍无法区分。
- **资源与停止条件**：已知预算、最小运行规模、何时扩大、收缩主张或停止；未知资源标为待确认。

优先比较能改变决策的结果。不要为了“实验丰富”堆多个相似数据集，也不要因一个精心控制的合成任务通过就声称现实世界普遍成立。

## 近邻比较与叙事

对关键近邻可用小表记录：来源及读取范围、同一问题/假设、共享机制、精确差异、证据状态。区分代码公开事实与是否复现；原论文声称的结果与自己验证的结果。

方法名、标题与开头的作用是让读者准确理解贡献。先确定可支持的主张，再讨论表达。一个有用的表达检查是：删掉方法名和形容词，读者是否仍知道新增了什么知识？

最重要的图不一定是架构图；可能是失效条件曲线、目标解释与替代解释的分叉预测、能力与成本边界，或适用条件示意。没有结果时只画实验设计或预期分歧，不伪造数据趋势。
