# Research Insight：开发回归与评测隔离

本目录属于仓库维护材料，不属于 `research-insight/` 安装目录。它不应被 skill 的运行时参考链接引用，也不应进入单独 skill 安装包。

## 材料与角色

- `prompts.jsonl`：20 条开发回归任务，每条仅包含 `id` 与 `prompt`，不包含标题暗示、预期回答或评分项。
- `rubric.md`：对应的验收点与失败信号，仅供评估者使用。包含任务原文，便于检查对应关系。
- `multiturn-plan.md`：评测组织者使用的真实多轮对照准备方案；尚未选定原始材料或运行，不提供给执行者。

执行者每次只接收一条任务、待测 skill 和完成任务必需的原始材料。评估者在执行结束后接收任务、实际轨迹/产物及该题评分标准；执行者不接收预期答案、建议解法或上一轮评价。

目录分离不等于文件访问权限隔离。在有完整仓库访问权的环境里，需要另外限制执行者可见文件，或把 skill 与必要输入复制到隔离工作目录。普通安装只取 `research-insight/`；整仓下载仍会包含本目录。

## 比较什么

在模型版本、原始任务、工具权限与预算尽量相同的独立上下文里比较：不使用 skill、只使用原则层、原则加针对性案例。后者只在已有具体取例目的时加载案例，记录实际读过哪些材料与实际成本。

以上用于比较资料层次。评估当前修改是否有帮助时，按[多轮方案](multiturn-plan.md)比较不使用 skill、已发布版本与修改版本，两种实验分别组织。

检查与问题相关的知识增量、近邻事实准确性、最小验证的判别力、主张—证据匹配和不适当套用案例的行为。不要把标题、措辞或固定答案复现当作研究质量。

## 什么不算独立效果证据

这些任务由已知开发问题整理，A–P 来自首版，Q–T 来自后续维护，都是开发回归规格，不是隐藏留出集。在已经读过评分标准的对话里执行或自评，不能证明泛化效果；改写同一道题也不会自动成为独立测试。

后续需另外保留未参与指令编写的任务及原始材料，并在执行端隔离评分信息。尚未构建或运行这类独立评测，本次文件与打包检查仅验证资料边界。
