# 真实多轮对照准备方案

状态：未选定原始材料，未运行。本文供评测组织者使用，不进入 skill 安装包，不提供给执行者。当前会话已经参与指令设计并读过评分材料，不能承担独立效果验证。

## 选取材料

从获授权的真实研究记录中选择尚未用于编写本次指令的任务，保留原始输入及影响判断的上下文。先做少量覆盖不同讨论需求的对照：

| 讨论需求 | 执行者需要的原始材料 |
| --- | --- |
| 展开模糊想法 | 用户原始观察或疑问，以及已经明确的约束；不附整理好的研究主线 |
| 理解混合结果 | 实际结果表、实验设置及必要日志，保留负面和不确定结果；不先写好诊断 |
| 澄清概念 | 用户正在讨论的定义、例子与当前问题，不额外添加训练或实验任务 |
| 根据纠正调整方向 | 起始材料及用户后续纠正的目标或新增事实，不附先前助手的推荐答案 |

无法取得相应真实材料时，将该项记为待准备。合成场景只能作为开发检查，并明确其来源；不将当前 A–T 的改写作为隐藏留出任务。未经允许公开的材料只在获授权环境中使用。

## 比较条件与隔离

比较不使用 skill、已发布 v0.2.0、当前修改版本。冻结实际 Git commit、修改补丁及包内文件哈希，不能只记容易漂移的分支名。

每个任务、条件与重复运行使用新的上下文。提供相同原始材料、模型设置、工具权限和预算；各条件只改变待测 skill。无 skill 条件也要排除同名技能的自动加载。执行者只可见该条件的 skill 和任务所需材料，不能访问完整开发仓库、评分标准或其他条件的输出。仅换工作目录不等于限制文件可见性；无法隔离时说明其限制。

案例读取由各版本自身规则决定，记录实际读过的文件，不人为强迫两版本读取相同案例。这个比较衡量整个版本的效果，不能单独归因于入口长度或案例策略。需要归因时再增加针对性对照。

## 多轮安排

先运行初始任务，再按预先确定的顺序逐轮提供新增事实或用户目标调整。后续消息对各条件保持相同，并且不依赖某个答案里才出现的候选或措辞。不要提前向执行者展示后续消息。

需要针对回答自由追问的真实互动可另行记录，保留完整轨迹；由于追问不同，它与固定消息回放分别分析。用户纠正若与已有事实冲突，观察模型是否指出冲突并澄清，而不是把机械服从当作调整能力。

## 观察与记录

评估者在运行结束后读取轨迹和原始材料，隐藏条件标签、交换展示顺序。评价针对实际内容，允许不同的合理研究路线，并用具体回答片段支持判断：

- 候选或解释是否贴合材料，差异是否实质；不以候选数量奖励发散。
- 是否把当前问题推进到更清楚的概念、可讨论的技术选择或有判别力的下一步；简单澄清无需生成新方向。
- 是否过早排除未验证但有价值的想法，或不断重复不影响当前决策的注意事项。
- 新事实或目标纠正后，是否修订相关判断，同时保留仍成立的事实与约束。
- 文献、结果与证据身份是否准确，案例是否被误当成当前课题的证据。
- 阅读、检索、耗时、输出长度及可获取的 token 用量，是否与获得的帮助相称。长度更短本身不代表更好。

为每次运行保存任务及材料版本、条件快照、模型与预算、实际读取和工具轨迹、逐轮输入输出、评估依据与分歧。评分者知道指令或仅由同一模型评判时，记录相应偏差；重大事实争议回到原始材料核对。

## 如何解释结果

逐任务比较收益与退化，不将各项简单相加成“研究能力总分”。少量任务只用于发现失败模式；模型波动、任务选择和评估者偏好限制结论。预算允许时用独立上下文重复，检查差异是否稳定。

依据结果修改指令后，这批任务成为开发回归材料。后续泛化检验另选未参与修改的任务，不能把同一批结果反复当作独立提升证据。通过格式或文件隔离检查不等于通过行为评测。
